# DevOps-project

Веб-приложение для производственного учёта материалов, нарядов и процессов.

## Запуск

~~~powershell/cmd
python main.py
~~~

## Правила внесения изменений

- Перед началом работы проверь текущий `git status`. Не смешивай в одном изменении несвязанные задачи.
- Сохраняй файлы в UTF-8. Для новых страниц используй общий `/styles.css`; не дублируй существующие правила оформления без необходимости.
- Новые API-маршруты должны проверять HTTP-метод, авторизацию, входные данные и принадлежность записей r текущему цеху. SQL-параметры передавай через placeholders, а не через конкатенацию строк.
- Не коммить файлы, которые исключены правилами `.gitignore`.
- Не изменять формат уже сохранённых дат, имена API-полей и значения статусов без описания совместимости.

### Обязательные команды проверки

Из корня репозитория перед передачей изменения:

~~~powershell/cmd
python -m py_compile main.py
git diff --check
~~~

## Запрещённые действия

- Не удалять `db.sqlite3`, таблицы или пользовательские записи ради прохождения проверки.
- Не отключать авторизацию, проверку принадлежности к цеху, ограничения базы данных, чтобы упростить реализацию.
- Не хранить секреты в исходном коде, README, HTML или запросах.
- Не выполнять `git push --force`/`git add --force`, переписывание общей истории, массовое удаление файлов.
- Не принимать изменение при не прохождении обязательными проверками, необъяснимыми изменениями в `git diff`, ошибками в логах сервера.

## Порядок приёмки

1. Автор проверяет область изменения и `git diff`, удаляет временные файлы и убеждается, что секреты и локальные данные не попали в список изменений.
2. Автор выполняет обязательные проверки для затронутого слоя: HTML/JavaScript, маршрутов, API или базы данных.
3. Для API проверяются авторизованный успешный запрос, отказ без сессии и отказ с невалидными данными. Для пользовательского сценария проверяются отображение результата и сообщение об ошибке.
4. Проверяется совместимость с существующими страницами `/login`, `/dashboard`, `/health`, общим `/styles.css` и текущей схемой SQLite.
5. Изменение принимается только после просмотра итогового diff и успешного прохождения проверок.
